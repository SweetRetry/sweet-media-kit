# Element Design

概念设计的目标是**有主张**：这个元素夸张了什么、舍弃了什么，观众只看一眼就读得出来。可读是底线，主张是筛选标准。读得出简报却换个题材也成立的方案，和读不出简报的方案一样淘汰。

模型一步写出的设计是同类题材里最常见的那一个。所以每个元素都先发散、推过头，再收回、锁定，不从简报直接写规格。

元素分三类，各读自己的 reference，六个阶段的类型细则都在里面：

| 类型 | 范围 | reference |
| --- | --- | --- |
| 角色 | 人物、生物、道具、载具等有独立轮廓的实体 | [character.md](references/character.md) |
| 场景 | 室内外空间、建筑、地貌 | [scene.md](references/scene.md) |
| 特效 | 法术、能量、爆炸、天气等有时间过程的现象，含它的声音特征 | [vfx.md](references/vfx.md) |

六个阶段依次推进，每个阶段结束于一道**关卡**。前一阶段定下的东西是后一阶段的硬约束：探索选定的大形不在细化里改，设计规格定了就不在主视觉里加新部件。后面阶段发现前面的问题时，回到出问题的阶段改，再把改动传到它之后的产出。

美术观感优先于与上一阶段的吻合。一张图偏离了锁定内容却明显更好看时，不替用户淘汰它：把它和吻合的版本一起给用户看，用户选了它，就把它立为新的锁定图，并更新被它推翻的阶段。

## 0. 工作方式

- 单个元素在工作目录建 `element-[元素英文名或拼音]/`，用户没给名字时先起一个暂名。设计档案写在 `element.md`，图片放在 `images/`，文件名以阶段号开头（`3-explore-a.png`、`6-test-leap.png`）。档案随阶段累积：简报、参考板、探索候选与选择理由、设计规格、图片清单。
- **套组**：多个元素同属一个世界时，建 `elements-[世界名]/`，每个元素一个子目录，先写一份 `rules.md` 再做第一个元素。套组规则写到可见特征：媒介与画风（笔触、颗粒、边缘、渲染质感，风格名必须拆开）、色彩体系与明度结构、留给特效而其他元素不得占用的一到两个色相、每类场景的光线基调、主材质组、各阵营的主形与线条倾向、只列实际要防偏差的排除项。每个元素的简报都服从它。先做承载主张最重的元素，特效排在它的宿主之后。
- **出图**：环境里有图片生成工具时直接生成，生成后亲自看图，逐条对照本阶段关卡，不过关的改 prompt 重生。没有工具时，每张图交付 prompt 与关卡条目，等用户回传图片后再验收、进入下一步。
- **按图的任务选模型**：版式与逐格内容必须照写的图（探索阵列、多视图、局部特写、序列帧）交给 gpt-image-2.6；设计稿与主视觉交给 Midjourney，它的图是设计母版。环境里没有其中一个时，按指令服从最强与审美最强各找替代。Midjourney 不保证结构准确，精度由 gpt-image-2.6 在母版上补：改数量与位置、去掉冲突部件、派生多视图，精修 prompt 先写唯一的改动，再逐项点名要保留的内容（主体、姿势、材质、纹理、笔触、画风、光线、构图），并写明不平滑、不重绘、不换风格。只写「其余不变」时，模型会滑回自己的默认画风。不拿锁定图和文字从头重画母版，重画会丢掉母版的美术质量。用户指定了某阶段的模型时照用，这个指定只管那一类图，不沿用到另一类图的阶段。
- **每次出图都提交已锁定的图作参考**：选定的探索候选、定稿设计稿都算。只靠文字复述锁不住形状。锁定内容在一张多格图里时，写明取哪一格。
- 模型带有 prompt 指南时，prompt 长度、语法与参数以指南为准，只对该模型生效。指南要求短 prompt 时，按视觉重要性从前往后截取已锁定内容，放不下的条目留给后续阶段的模型落实。
- 一次只提交一个生成任务，看图验收后再提交下一个。调用超时先查任务状态，仍在运行就等待，不重复提交。
- 出图 prompt 里部件按几何写：形状、两端、边缘、厚薄、是否完整可见。不用整物名词或比喻指代局部，模型会把整物画出来（写「某物的碎片」会带出那件东西的完整特征，写「像某物」会直接画出某物）。
- 出图 prompt 用目标图片模型最擅长的语言，写齐这张图的用途与版式、背景，以及到这一阶段为止已经锁定的内容：探索阶段只写形状，第 4 阶段起加媒介与画风，第 5 阶段起加完整设计规格。已有定稿图时作为参考图一起提交，并写明它只锁外观。
- **选择权**：简报、探索选型与最终方向由用户决定。你给出推荐与理由，用户确认后进入下一阶段。用户要求一次做完时，这三处都按推荐执行，交付时列为「代选」。
- **无图又不停**：没有生图工具且用户要求一次做完时，需要看图的关卡改为两步：先用文字能核的部分做选择（探索按变化轴的差异与主张落点选，设计按规格是否自洽选），再把只有看图才能判的条目列进交付的「待看图验收」清单，写明它们会推翻哪个选择。

## 1. Concept Brief（概念简报）

写成五项，每项都要能被画出来。身份、冲突与核心的类型写法见 reference：

- **一句话身份**：它是什么，正处在什么处境里。
- **冲突**：写成看得见的两股对立，设计会让它们同框。画不出来的冲突改写到画得出来为止。
- **核心**：这个元素最要紧的那件事发生在哪个部位。这个部位就是后面全部设计的视觉焦点。
- **情绪关键词**：3 个能对应到形状与明暗的词（沉重、锋利、轻盈、阴冷、张扬），不用「酷」「帅」「有气质」。
- **设计主张**：一句话写明夸张什么、舍弃什么，都落到形状、比例、材质或节奏上（`躯干压成一整块竖直的板，四肢细到只剩线，全身不留一处曲面`）。主张必须从冲突或核心推出来，并且排除掉一批常见做法；「更有风格」「更夸张」不排除任何东西，不算主张。夸张到什么程度按媒介与画风定，写实媒介也要有主张，落在比例与取舍上。

再从需求推出约束：媒介与画风、用途（给 3D 建模用、插画、视频生成要跨镜头保持一致）、所属世界的时代与技术水平，以及这个元素要经历的状态（受伤、损毁、激活、时段变化）。属于套组的直接取套组规则。推不出且不同答案会导向不同设计的项，一次问完，至多 4 问，每问 2–4 个选项并标出推荐项；用户要求一次做完时不问。推不出的其余项按最贴合需求的选项写，记为代选。

**关卡**：五项都能直接对应到画面元素；把主张换给同题材的另一个简报不再成立；用户确认简报。

## 2. Moodboard（参考板）

收 15–30 张参考，分进 reference 给出的五栏。每张参考只借一个具体属性，写成 `[来源] → 借[属性]`（`十六世纪哥特板甲 → 借甲面竖向凹槽的光棱`），不整体照搬任何一个完整设计。

- **跨域取材**：每栏至少来自两个领域。取自虚构作品（游戏、动画、影视美术）的参考不超过全板四分之一，其余取自现实（历史服饰、动植物与矿物、工业器物、建筑、宗教器具、自然现象）。主要从同类作品取材的设计会长成那个类型的平均脸。
- 已知作品的设计只能作单项属性参考；用户给的参考也按此拆开借用。
- 拿不到图片时，把参考写成文字条目（来源 + 具体属性），效果相同。
- 收齐后提炼 3–5 条**设计规则**，写进档案（`主形为倒三角`、`冷硬金属对暖色旧皮革`、`全身竖向线条，只有核心部位打破`）。至少一条把设计主张落成可检查的规则。后面每个阶段都对照这几条。

**关卡**：五栏都有参考；每条参考写明借了什么；设计规则能追溯到具体参考与简报。

## 3. Exploration（发散探索）

先定**变化轴**（见 reference），再出 6–12 个候选。设计规则已经锁定取值的轴不再变，在其余的轴上发散。每个候选用一行写清它在各轴上的取值，任意两个候选至少在两条轴上不同。

- **推过头**：至少三分之一的候选把设计主张推到你认为过头的程度。收回比加码容易，探索里没有过头的候选，定稿就只会停在保守的那一端。
- 候选的画法与版式见 reference。每个候选单独写描述，分格出图时每格各写一次；只写「一排不同的方案」时，模型会把一排画成同一个方案的微调变体。

**关卡**：

- 缩到缩略图大小仍能互相区分。
- 每个推荐的候选都看得出设计主张，也看得出简报的冲突或核心落在哪里。
- 和知名设计撞形的淘汰；换给同题材的另一个简报也成立的淘汰。
- 推荐 2–3 个并逐个写理由，其中至少一个来自推过头的那批。用户选定后进入细化。

## 4. Design Exploration（设计细化）

每个选定的候选是一个方向，在它的大形里细化，大形保持不变。每个方向出一张设计稿，按 reference 的顺序定细节。

- **形状层级**：大形定气质，中形定功能，小形定质感。细节密度按约 `70 / 20 / 10` 分区，最密的集中在核心部位与次焦点，其余留出大片安静区让焦点成立。
- **收回有度**：推过头的方向在这里收回到媒介与用途承受得住的程度，只收妨碍可读或功能的部分。收回后主张仍要在缩略图大小看得出，看不出就是收过了。
- **颜色**：先定明度结构，转成灰阶后主体、核心部位与背景仍分得开；再定色相。主色、辅色、点缀色约按 `60 / 30 / 10` 分配。

**关卡**：用户选定一个方向后，写出**设计规格**，它是后面所有出图的唯一外观依据：

- **外观不变量**：8–15 条全程不变的可见事实，每条写到部位、形状与数量，不对称部件写明左右，按视觉重要性排序。prompt 照此顺序写，长 prompt 里靠后的条目最容易丢。第一条写设计主张落成的可见事实。
- **状态变体**：简报里列出的每个状态各一条，写清与常态相比哪些可见事实改变。
- reference 要求的类型专项（场景的空间布局、特效的时间曲线与物理作用等）。

设计规格只锁外观；姿势、机位与时段内的细微光影按需变化，不算新部件。

## 5. Key Art（主视觉）

一张图同时交代气质、形体与核心：

- 画面让核心正在发生，焦点落在核心部位；大形仍保留探索阶段的辨识特征。
- 机位与光线服务情绪关键词，明暗结构沿用设计稿。
- 以定稿设计稿为参考图，prompt 写入完整设计规格。

**关卡**：逐条对照设计规格，每条在图里都看得到且没有改变；画面里没有规格外的新部件；主张没有被渲染细节冲淡。想到更好的部件时，先改设计规格并回到第 4 阶段确认，再出图。

## 6. Validation（验证）

按 reference 出验证图：角色出多视图与动作测试，场景出平面图、反打与变体，特效出序列帧与分级。验证图检查设计在换角度、换状态、动起来之后是否还成立。

验证暴露结构问题时，改设计规格，再重出受影响的验证图与主视觉。

## 交付

`element.md` 写全简报、参考板与设计规则、探索候选与选择理由、设计规格、各阶段图片清单（文件名、用途、它锁定什么）。回复列出产出文件、代选的项，以及仍未解决的问题与它们所在的阶段。
