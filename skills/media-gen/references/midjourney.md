# Midjourney V8.2

经兔子 API 的 midjourney-proxy 协议调用，所有网络调用经 `scripts/mj.py`，用法看 `mj.py -h`。按次计费，每次 imagine 或按钮操作 0.35，查询不计费。`mj.py` 只出 V8.2；用户要别的 MJ 版本或 niji 时说明不支持。

V8.2 是 2026-07-24 起的默认模型。它比 V7 更能跟随长而具体的描述，自带一层偏大胆、精致的默认美学，原生 2K（`--hd`）。

## 正文

- **写成完整的描述句，不堆关键词。** 按主体、动作或状态、环境、构图与景别、光线、色彩、媒介与风格的顺序，越重要越靠前。主体写确切数量（“three cats”）和可见特征。
- **写想要的状态，排除项交给 `--no`。** 正文里的“没有 X”会把 X 带进画面。`--no` 后用逗号分隔单个词，多词短语会被审核逐词误判。
- **画面文字放进双引号**，用短的拉丁字母短语，配 “with the words” 或 “written”。字出错时加 `--raw` 或降低 `--s`。
- **主次靠句子表达。** V8 不支持 `::` 权重，也不支持 `{a, b}` 排列（脚本拒绝，因为排列会拆成多个计费任务）。
- **英文写正文。** 接口不翻译中文需求，交付前译成英文描述。

## 参数

参数放在正文末尾，`--` 前留空格，后面不加标点。`mj.py` 会删掉任何版本参数，再追加 `--v 8.2`。

| 参数 | 取值 | 何时用 |
| --- | --- | --- |
| `--ar W:H` | 整数比例，默认 1:1，SD 最大 14:1，HD 最大 4:1 | 每次都按交付用途显式写 |
| `--hd` / `--sd` | HD 原生 2K（1:1 为 2048px），SD 为 1024px | 终稿或要细节时用 `--hd`；HD 不能再放大 |
| `--raw` | 关闭默认美学 | 摄影写实、产品图、要文字准确、要严格按描述 |
| `--s` | 0–1000，默认 100 | 越高越偏模型审美；同时放大 `--p` 与 moodboard 的强度 |
| `--c` | 0–100，默认 0 | 四张之间要更大差异时提高 |
| `--w` | 0–3000，默认 0 | 要怪异、非常规时提高；会破坏 seed 一致性 |
| `--seed` | 0–4294967295 | 对比单个参数的影响；V8 下约 99% 一致，不是完全复现 |
| `--no` | 逗号分隔的单词 | 排除元素 |
| `--tile` | 开关 | 无缝贴图；放大会破坏无缝 |
| `--sref` | 图片 URL、数字 code 或 `random`；`--sw` 0–1000，默认 100 | 锁风格。正文只写内容，不写和参考冲突的风格词 |
| `--p [id]` | 个人化 profile 或 moodboard | 用户有自己的 profile 时 |
| `--iw` | 0–3，默认 1 | 有垫图时调垫图影响力 |
| `--exp` | 实验美学参数，范围未公开 | 用户明确要求时 |

V8 去掉的参数（`--q`、`--oref`、`--cref`、`--stop`、`--style raw`、`--niji`、`--turbo` 等）由脚本拒绝并给出替代写法。

## 参考图

- **垫图**锁内容与构图。用 `--ref`，本地文件转 base64，URL 放到正文最前面；可重复传多张。只有图没有正文时不能用 `--s`、`--w`。
- **风格参考**用 `--sref`，只锁风格不锁内容。
- 角色或物体一致性没有专门参数（V8 已去掉 `--oref`、`--cref`），用垫图加正文里写清身份特征。

## 提交与后续

1. 先跑 `mj.py imagine "<prompt>" --dry-run`，修到通过。
2. 报费用后去掉 `--dry-run` 提交。单轮超过 4 次提交先等用户确认。脚本轮询直到完成，优先下载 `imageUrls` 中的独立图片。
3. 首次运行时检查摘要里的 `prompt` 含 `--v 8.2`，不含就告诉用户版本没生效。
4. 放大、变体、重抽用 `mj.py action <task_id> <U1-U4|V1-V4|reroll>`，各计一次费。

任务失败时把 `failReason` 原样告诉用户。code 24 是敏感词，按返回的词改写正文。超时的任务用 `mj.py fetch <task_id>` 继续取。
